# AgentEnvForge 0.2.0

The first release of AgentEnvForge: define a software-engineering task once, run any agent
against it in a locked-down Docker sandbox, grade the result with hidden tests in a fresh
sandbox, and reproduce every run. Version 0.2.0 adds **batch experiments**: tasks × agents
× repetitions with bounded concurrency, statistics and reports.

## Highlights

- **Batch experiments.** `agentenv experiment validate | inspect | run | report` and
  `agentenv experiments list | show`. A versioned experiment file combines tasks, agents
  and repetitions; runs execute on N workers with backpressure, a circuit breaker for
  broken infrastructure, and Ctrl+C that cancels and cleans up active runs while keeping
  completed results.
- **Statistics you can trust.** Runs are scored or excluded by stage (an unreachable model
  server is not an agent failure), success rates carry 95% Wilson intervals, pass@k is
  reported only when the sample supports it, and reference and baseline agents validate
  every task.
- **Reports.** Each experiment writes `report.md`, `summary.json`, `runs.csv`,
  `failures.csv`, charts and a reproducibility manifest, with host paths and account
  details removed so results can be shared.
- **Agents.** Programs inside the sandbox, Python adapters on the host, local models via
  Ollama, and hosted Claude models via Claude Code, whose only tools act inside the offline
  sandbox.
- **Benchmarks** with committed results: throughput scaling with workers, failure isolation
  (also run in CI), and Claude Haiku 5.5, Sonnet 5.5 and Opus 5.5 on three bug-fix tasks.

## Install

```bash
git clone https://github.com/M-amir1998/AgentEnvForge.git
cd AgentEnvForge
git checkout v0.2.0
uv sync
uv run agentenv doctor
```

Requirements: Python 3.12+, Docker (Desktop or Engine), git. Charts need the optional
`plots` extra (installed by `uv sync`).

## Upgrading from a development version

An existing `~/.agentenvforge` database is migrated automatically on first use (two new
tables for experiments, and a column for the experiment file's location). Existing runs are
kept.

## Known limitations

Docker containers share the host kernel; treat the sandbox as a defence-in-depth boundary,
not a VM-grade one. Experiments run on one machine; interrupted experiments cannot be
resumed yet, and infrastructure failures are not retried automatically. The full list is in
[docs/development/status.md](../development/status.md).
